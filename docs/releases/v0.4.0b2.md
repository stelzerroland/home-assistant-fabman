# v0.4.0b2 - Confirm direct member activation from the activity log

This beta fixes a false Home Assistant error after an internal-API `switch-on`
was accepted for a selected member. The internal API documents the response as a
string, so the integration now confirms the resulting activity log directly
instead of expecting a bridge-command object.

For `https://internal.fabman.io/api/v1`, the integration polls for up to 30
seconds for one new allowed usage on the resource, confirms that the log belongs
to the requested member and re-reads it before reporting success. It does not
change the log or retry activation. Public-API behavior and API-key-member
defaults are unchanged.

If the previous beta showed an attribution error, the action may still have been
executed. Check Fabman's activity log and the physical resource state before
trying again.

## Install or roll back in HACS

Open **HACS → Fabman → ⋮ → Redownload**, enable **Show beta versions**, select
**v0.4.0b2**, download and restart Home Assistant.

To roll back, redownload stable **v0.3.0** and restart Home Assistant.

## Validation

All **346 tests pass** on Home Assistant **2026.10.1** and **2026.10.2**; Ruff
checks pass. HTTP behavior was tested with a local simulated Fabman API. No live
Fabman bridge activation was sent during automated validation.
