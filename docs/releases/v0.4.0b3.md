# v0.4.0b3 - Direct member activation on all Fabman APIs

This beta sends a mapped or explicitly selected member directly in the
`switch-on` request on both the production and internal Fabman APIs. The API URL
no longer changes the activation flow. Fabman checks the selected member's
permissions. Calls without a selected member continue to use the API-key member.

The integration confirms the resulting activity log for selected-member
activations and does not reassign it afterward. It never retries an activation
after an error.

Fabman's HTTP 422 responses now produce specific Home Assistant errors:

- `data.noPackage`: no package allows the member to use the resource at that time.
- `data.noPermission`: the member lacks permission to use the resource at that time.
- `message: "Invalid member ID"`: check the Home Assistant mapping or the
  `member_id` passed to `fabman.turn_on`.

## Install or roll back in HACS

Open **HACS → Fabman → ⋮ → Redownload**, enable **Show beta versions**, select
**v0.4.0b3**, download and restart Home Assistant.

To roll back, redownload stable **v0.3.0** and restart Home Assistant.

## Validation

The automated tests were not run for this release. `git diff --check` passed.
Please test this beta against your Fabman production account before relying on
the direct-member path.
