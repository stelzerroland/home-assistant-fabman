# v0.2.0b4 - Automatic resource synchronization (beta)

New supported Fabman resources now appear automatically in HA after a successful
resource refresh, without reloading the integration. Activity, Connectivity,
the existing text status sensor and switch are added to the resource's device.
Resources that acquire a supported bridge later are discovered at that point.

## Lifecycle behavior

The inventory explicitly requests `active`, `locked`, `archived` and `deleted`
states. Previously the default Fabman list omitted archived/deleted equipment.
Pagination keeps the same filters; a later-page failure cannot publish a partial
inventory. The same polling/webhook refresh drives discovery.

- New active/locked supported resources are added once, including while HA runs.
- Historical archived/deleted resources that HA never knew are not newly added.
- Known archived/deleted or missing resources remain unavailable, without automatic
  registry deletion. Their switches cannot send commands and door timers stop.
- Reactivation without manual cleanup restores the same entity/device identities,
  including after reload. Historical data follows HA's normal recorder retention.
- Source renames update default device/status/switch names. User-provided HA names,
  disabled preferences and existing entity IDs are preserved.
- All four entities expose a `resource_state` attribute for diagnosis.

HA's device page can now remove an archived/deleted device or one absent from a
complete list. Removal is refused for active/locked equipment, during API failure,
or when malformed unidentified rows make the inventory uncertain. This action is
local HA cleanup; it never deletes or modifies Fabman resources. Cleaned inactive
devices do not immediately reappear. Reactivating a resource allows discovery again.

Review automation inputs before manually removing devices or retiring resources:
an unavailable input can still prevent automatic light-off. Automations are not
edited by the integration. Missing lifecycle fields retain the earlier active
behavior for compatibility; unrecognized explicit states are not considered current.

## Validation

193 tests pass against each of Home Assistant 2026.10.1 and 2026.10.2. These include
real HA platforms/registries for discovery, duplicate prevention, naming overrides,
archive/reload/reactivation, disabled entities, cleanup and API failure recovery.
An authorized read-only API check confirmed the all-state query and pagination.
No real resource or bridge was created, archived, deleted or switched, and the
production HA installation was not changed.

## Update

In HACS, open Fabman > **Redownload** > **Need a different version?** > `v0.2.0b4`
(enable beta/prerelease versions if necessary), download, then **restart HA**.
Keep the existing configuration entry. Once this code is loaded, later new
resources are discovered by polling/webhooks without further restarts.

Polling remains enabled by default at 30 seconds. Discovery depends on successful
refreshes; with polling disabled it depends on webhook delivery. All-state
inventory may contain more pages than the previous active/locked-only request.
Stable-only HACS users remain on v0.1.1. See the
[activity contract](../activity-contract.md) for remaining pilot restrictions.
