# v0.2.0b2 - Fix completed machine usage (beta)

The first beta reported many completed machine usages as `unknown` with
`invalid_stop_timestamp`. Its validator incorrectly treated `lastUsed.at` as the
usage start and required `stoppedAt >= at`.

Read-only API checks found that `lastUsed.at` matched `updatedAt` in both examined
resource logs; the actual start was `createdAt`. A stop before this update time
is valid, including updates made hours after a usage ended.

This beta removes that incorrect ordering requirement. Recognized completed
machine usage with valid, timezone-aware, nonfuture timestamps becomes `off`.
This applies to both Activity binary sensors and existing status/switch entities.
Missing or malformed timestamps, future timestamps, null usage and ambiguous
stop types still remain `unknown`.

## Validation

- 155 tests pass on each of Home Assistant 2026.10.1 and 2026.10.2.
- Regression fixtures retain observed data shapes with synthetic identities/dates.
- In a read-only snapshot of 105 supported resources, corrected evaluation gave
  12 on, 90 off and 3 unknown. The 71 false timestamp errors disappeared.
  The remaining unknowns were two offline stops and one null usage.
- No real bridge commands were sent, and no HA configuration was changed.

These snapshot counts are diagnostic observations, not expected permanent counts
or proof of current physical bridge connectivity. The existing
[activity contract and pilot limitations](../activity-contract.md) still apply.

## Update through HACS

Open Fabman in HACS, choose **Redownload**, select **Need a different version?**
and `v0.2.0b2`, then download. Enable beta/prerelease versions if necessary.
**Restart Home Assistant after this update**, since b1 has already been loaded.
Do not remove or recreate the Fabman configuration entry.

Entity identities and configuration are preserved. Continue the passive comparison
before changing production automations. Stable-only users remain on v0.1.1.
