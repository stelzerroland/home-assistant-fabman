# v0.4.0b4 — Opt-in QR resource controls

This beta adds a shared Fabman panel inside Home Assistant. Administrators enable
individual machines and doors in the integration options, then copy or print QR
links from the Fabman sidebar. Every resource starts with direct links disabled.

Scanning navigates to a confirmation page. Starting usage uses the authenticated
HA user's existing Fabman mapping; unmapped users use the API-key member.
Machine actions are explicit on/off commands based on a fresh observed state.
Doors request opening; Nuki, POS and check-in terminals are excluded.

The backend enforces opt-in, HA entity permissions, user-bound 60-second
confirmations, snapshot checks and single submission. Command results and member
confirmation are separate. Reloads interrupt pending QR operations; a restart loses
their in-memory history. Check unclear outcomes before a manual retry.
External Fabman controls can still race the final read and send.

The v0.4.0b3 direct-member activation changes remain included. Updating requires
an HA restart. No dashboard configuration, new API key or configuration migration
is required. No resources are automatically opted in during an upgrade.

Automated validation covers Python regressions and Chromium mobile layouts with
synthetic HA responses, including decoding generated QR codes back to their URLs.
Physical Android/iOS camera-to-app handoff, login continuation and live hardware
remain installation acceptance checks.

See the README's QR direct links section for setup and operational details.
