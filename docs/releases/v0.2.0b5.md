# v0.2.0b5 - Clear completed short door commands (beta)

A door switch could remain assumed on indefinitely while Activity and the text
status stayed unknown. Reconciliation only accepted a new door grant while the
release was still on. A three-second release could finish before the next full
resource snapshot arrived, so the accepted opening was never acknowledged.

This beta accepts a new allowed, valid door grant as evidence that the opening
occurred, including when its release window has already expired. In that case the
command assumption clears and switch, Activity and status all report off directly.
An observed active release still expires locally at its original deadline.

The comparison uses usage IDs when the previous usage has an ID, so modifying
an old usage timestamp does not confirm a new opening. Older responses without
a baseline usage ID retain the timestamp fallback. The baseline is captured before
the POST to handle grants arriving during that request.

An HTTP 201 alone still does not prove a completed opening. Old grants, explicit
denied usage, offline bridges, missing IDs when required, or invalid release data
do not clear the assumption. Command-completion polling is still outside this fix.
No artificial release is started at the time an expired grant is finally observed.

## Validation

- 203 tests pass on each of Home Assistant 2026.10.1 and 2026.10.2.
- The delayed-expired-grant regression failed on the previous code and passes now.
- Real HA entity platform tests verify assumed on/unknown transitioning to off
  across the switch, Activity and text status.
- On 2026-10-21, the owner authorized live testing of one specific door. Two
  short opening commands were sent: one to reproduce/inspect the API flow and
  one through the corrected switch/coordinator code. The corrected run observed
  off -> assumed on -> confirmed on -> off for the configured three-second window.
- No other equipment, Fabman configuration or production HA configuration changed.

The live result validates the release state reported by the code and API, not a
physical door contact. See the [activity contract](../activity-contract.md) for
remaining pilot restrictions.

## Update

In HACS, open Fabman > **Redownload** > **Need a different version?** > `v0.2.0b5`
(enable beta/prerelease versions if needed), download, then **restart HA**.
The existing configuration and entity identities are preserved. Reloading clears
the previous in-memory pending command; the corrected logic handles future opens.
Stable-only installations remain on v0.1.1.
