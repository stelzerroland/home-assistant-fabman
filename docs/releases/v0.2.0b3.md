# v0.2.0b3 - Bridge Connectivity (beta)

Each supported Fabman device now has a binary sensor named **Connectivity**,
alongside Activity, the existing status sensor and switch. It is enabled by
default and uses HA's `connectivity` device class (Connected / Disconnected, or
localized equivalents). Existing entity identities are preserved.

## State behavior

- `bridge.offline: false`: Connectivity is `on`; usage determines Activity.
- `bridge.offline: true`: Connectivity is `off`; Activity is `unknown` with
  `status_reason: bridge_offline`, even if an old usage ended normally.
- Missing, null or wrongly typed offline flags: both are `unknown`.
- API failure or resource missing from a complete snapshot: both are `unavailable`.

The activity rule also applies to the existing text status sensor and observed
switch state. An accepted, unconfirmed switch command still exposes its requested
state as assumed; it does not alter Connectivity or manufacture confirmed usage.
Door release timers cannot turn an offline door's activity into `off`.

Connectivity is Fabman's server-reported assessment, not an immediate hardware
measurement. It depends on configured heartbeat detection and the next successful
HA refresh. Existing polling/webhooks supply both sensors without extra API calls.

## Validation

177 tests pass against both HA 2026.10.1 and 2026.10.2, including real HA state
publishing, device grouping, stable registry identities across reload, API outage,
offline/online recovery, malformed flags, pending commands and door timer cleanup.
Read-only checks of an offline machine and an offline door confirm Connectivity
off and Activity unknown. No bridge commands or production HA changes were made.

Remaining pilot restrictions and the historical, untested HA 2023.1.0 HACS minimum
are documented in the [activity contract](../activity-contract.md).

## Update

In HACS, open Fabman > **Redownload** > **Need a different version?** > `v0.2.0b3`
(enable beta/prerelease versions if necessary), download, then **restart Home
Assistant**. Keep the existing Fabman configuration entry. The Connectivity
entities are created on the existing devices after restart.

Stable-only users remain on v0.1.1. Before adopting this beta's Activity sensors
in production lighting, repeat the passive comparison and account for offline
resources now deliberately remaining unknown rather than reporting old off states.
