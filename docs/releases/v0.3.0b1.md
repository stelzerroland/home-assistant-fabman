# v0.3.0b1 - POS authorization events and Nuki support

This is a beta for testing in Home Assistant. The latest stable release remains
v0.2.0. The beta adds read-only POS authorization events and bridge-linked Nuki
resources; live behavior with Happylab hardware still needs testing.

## POS resources

POS resources expose a Fabman bridge Connectivity binary sensor and an
Authorization event entity. The event entity fires `authorized` for new successful
(`allowed`) resource-log entries. It omits member details and does not replay
historical entries during initial setup. Polling or a webhook-triggered refresh
collects later entries.

POS has no switch or on/off activity state. Fabman describes the POS terminal
bridge as an authorization-check integration that does not switch equipment on
and off like a normal bridge. Connectivity reflects the Fabman bridge, not the
terminal's actual power state.

## Nuki resources

Nuki resources retain the Fabman access switch. Their Activity state reflects the
configured access interval and turns off locally after `maxOfflineUsage`, as for a
door. Additional entities report the synchronized Nuki lock state and battery
percentage. The Lock binary sensor uses Home Assistant's standard semantics:
`on` means unlocked and `off` means locked. State transitions and unknown values
remain unknown. Nuki `turn_on`
uses the action configured in Fabman; the integration does not expose a native HA
lock command, and no action can be selected from HA. Opener and Box states use
different codes and are therefore not reported as locked/unlocked.

Nuki state data is read from Fabman and may be stale until Fabman refreshes its
connection to Nuki. The bridge Connectivity sensor reports Fabman bridge state,
not Nuki's network reachability. Nuki action behavior, including explicit
`turn_off`, has not been tested against live Happylab hardware in this beta.

## Install or roll back in HACS

In HACS, open **Fabman → ⋮ → Redownload**, enable **Show beta versions**, select
**v0.3.0b1**, download it and restart Home Assistant. To return to the latest stable
version, repeat the process with beta versions disabled and select **v0.2.0**.

The beta does not change the existing API token, polling configuration, stable
entity unique IDs or member assignment action. New Nuki and POS entities will be
added for matching resources. When returning to v0.2.0, check automations that
refer to beta-only entities. No Fabman equipment or settings are changed by that
rollback.

## Validation

Automated tests cover POS authorization filtering and privacy, cursor behavior,
Nuki state mapping, the timed access interval, entity discovery and API pagination.
Live checks of Nuki commands, battery/lock-state refresh and POS authorization
events remain part of the Happylab pilot.
