# v0.3.0b2 - Command confirmation timeout

This beta adds a bounded confirmation wait to the existing v0.3.0b1 POS/Nuki beta.
The latest stable release remains v0.2.0. The unreleased check-in attendance
extension is not included.

## Behavior

- An accepted on/off command has a 30-second local confirmation deadline.
- The deadline also runs with periodic synchronization disabled or API reads failing.
- Without a matching observation, the switch stops presenting an assumed on/off
  state. Switch, Activity and Status remain unknown; Activity/Status expose
  `status_reason: command_timeout` instead of `command_unconfirmed`.
- A persistent Home Assistant notification explains that execution was not confirmed.
- An unchanged old door grant cannot confirm an opening. A later matching API
  observation can clear the error and dismiss its notification.
- Confirmation, replacement, resource removal and integration unload cancel the
  corresponding local timer. A timeout does not forge recovery from an API outage.

The timeout does not retry activation, send an automatic off command, or cancel a
command still queued at Fabman. Check the server/hardware before retrying. This
tracking is in memory and is not restored after a reload or Home Assistant restart.

## Scope and limitations

This release improves command feedback; it does not add `activate` handling to the
separate Android Fabman Bridge application or fix hardware that cannot execute a
remote activation. No physical opening commands were sent during validation.

Custom dashboard cards must interpret `command_timeout` to display a distinct
failure label such as "Opening not confirmed". The existing custom Happylab card
is outside this integration release; it may otherwise continue to show its generic
unknown-state label. The persistent HA notification is provided by the integration.

## Install or roll back in HACS

Open **HACS → Fabman → ⋮ → Redownload**, enable **Show beta versions**, select
**v0.3.0b2**, download and restart Home Assistant.

To return to the previous beta, redownload **v0.3.0b1** and restart. To return to
stable, disable beta versions and select **v0.2.0**; review beta-only POS/Nuki entity
references before doing so. Updating or rolling back does not cancel queued Fabman
commands.

## Validation

Automated tests cover timeout delivery without polling, both requested states and
all supported switch resource types; unchanged snapshots, timely and late
confirmation, in-flight reads, API failures, command replacement and unload.
All **287 tests pass** on each of Home Assistant **2026.10.1** and **2026.10.2**.
Python error checks and whitespace checks also pass.
