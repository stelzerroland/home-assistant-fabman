# v0.4.0b1 - Direct member activation on the internal Fabman API

This beta uses Fabman's new optional `member` value in the `switch-on` request
when the integration is configured for `https://internal.fabman.io/api/v1`.
Stable v0.3.0 remains the latest stable release.

## Member attribution

For a Home Assistant user with a configured member mapping, or a context-free
`fabman.turn_on` action with `member_id` or `email_address`, the integration
resolves and validates the member before activation, then sends the numeric ID
directly to `switch-on`. Fabman evaluates that member's permissions for the
resource. The integration confirms the returned command and the unique resulting
usage log without editing the log afterward.

The configured API URL controls the behavior. Direct member activation is enabled
only for `https://internal.fabman.io/api/v1` (also accepting a trailing slash or
explicit default HTTPS port). For `https://fabman.io/api/v1` and every other API
URL, the integration retains the v0.3.0 flow: start with the API-key member, then
reassign the confirmed activity log with optimistic locking. That path does not
check the selected member's Fabman permissions. If no member is selected, both
paths activate as the API-key member.

The integration does not fall back to the API-key member or retry activation if
the internal API rejects the selected member. A confirmation error after Fabman
has accepted activation also does not trigger another activation; inspect the
resource's activity log before taking further action.

## Install or roll back in HACS

Open **HACS → Fabman → ⋮ → Redownload**, enable **Show beta versions**, select
**v0.4.0b1**, download and restart Home Assistant.

To roll back, redownload stable **v0.3.0** and restart. This beta changes only
member attribution for installations configured with the internal Fabman API.

## Validation

All **343 tests pass** on Home Assistant **2026.10.1** and **2026.10.2**; Ruff
checks pass. HTTP behavior was tested with a local simulated Fabman API. No live
Fabman bridge activation was sent during validation; test the direct-member path
on a controlled internal installation before relying on it for production access.
